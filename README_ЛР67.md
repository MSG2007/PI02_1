Алгоритмы сортировки

Сортировка выбором (Selection Sort) — это алгоритм сортировки, который находит наименьший (или наибольший) элемент в массиве и перемещает его в начало (или конец). Процесс повторяется, пока все элементы не окажутся упорядоченными.
Анализ алгоритма:
Алгоритм состоит из двух циклов:
Внешний цикл (for (int i = 0; i < n - 1; ++i)): Проходит по каждому элементу массива слева направо, начиная с первого элемента и заканчивая предпоследним.
Внутренний цикл (for (int j = i + 1; j < n; ++j)): Начинается с текущего индекса внешнего цикла плюс единица и проверяет оставшиеся элементы, ища наименьший элемент среди всех правее текущего.
Когда найдена минимальная позиция (minIndex), осуществляется обмен значений текущего элемента и найденного минимума с использованием стандартной функции std::swap(), которая автоматически меняет значения переменных.
Временная сложность алгоритма: O(n²), где n-количество элементов в массиве.
Почему O(n²): в алгоритме присутствуют два вложенных цикла, где каждый из них в среднем или худшем случае зависит от n. Внутренний цикл может выполняться до n раз для каждого из n итераций внешнего цикла, что приводит к квадратичной зависимости.

Сортировка обменом (пузырьком) (Bubble Sort) — алгоритм проходит по списку несколько раз, сравнивая соседние элементы и меняя их местами, если они находятся в неправильном порядке. Процесс повторяется до тех пор, пока список полностью не отсортируется.
Анализ алгоритма:
Алгоритм реализуется с двумя основными этапами:
Внешний цикл:Отвечает за контроль общего числа проходов по списку. Так как на каждом прохождении наибольший элемент движется к своему правильному месту в конце, число нужных проходов совпадает с длиной массива.
Внутренний цикл:Осуществляет непосредственное сравнение пары соседних элементов и их замену, если порядок нарушен. За счёт этого внутренние проходы уменьшают область проверки на каждом новом витке, так как крайние элементы становятся фиксированными и уже правильно расположенными.
Временная сложность алгоритма: O(n²)
Почему O(n²): В худшем случае, как и сортировка выбором, требует n*(n-1)/2 сравнений и потенциальных обменов.

Сортировка вставками (Insertion Sort) — алгоритм сортировки, при котором каждый новый элемент вставляется в правильную позицию среди ранее отсортированных элементов. Он начинает с первого элемента и перемещается вправо, сравнивая каждый элемент с предыдущими элементами и вставляя его на правильное место.
Анализ алгоритма:
Основной цикл: for i in range(1, len(arr)): проходит по каждому элементу массива, начиная со второго элемента (первый элемент изначально считается отсортированным) и вставляет его в правильную позицию среди уже отсортированных элементов.
Внутри вложенного цикла (сдвиги элементов): while j >= 0 and key < arr[j]: мы "пробегаем" по уже отсортированной части массива, сдвигая элементы вправо, пока не найдём место для вставки key. Размещение текущего элемента: arr[j + 1] = key. Устанавливаем текущий элемент на освободившееся место, которое соответствует его правильной позиции.
Временная сложность алгоритма: O(n²)
Почему O(n²): В худшем случае общее количество сдвигов и сравнений составляет 1 + 2 + 3 + ... + (n-1) = n*(n-1)/2

Сортировка слиянием (Merge Sort) — алгоритм состоит в разделении массива пополам, сортировке половин и их слиянии.
Анализ алгоритма:
Внешний цикл (рекурсивная функция void mergeSort(vector<int>& arr, int left, int right)) разделяет массив на мелкие части, отсортировывает их, а потом сливает их обратно.
Внутренний цикл(функция void merge(vector<int>& arr, int left, int mid, int right)) создаёт единый отсортированный массив.
Фактического обмена (swap) элементов в традиционном смысле тут нет. Вместо этого происходит процесс переноса элементов из временных массивов (L и R) обратно в исходный массив (arr)
Временная сложность алгоритма: O(n log n)
Почему O(n log n): 
Массив делится на части рекурсивно. Глубина дерева рекурсии — это логарифм по основанию 2 от размера массива nn.
На каждом уровне рекурсии проводится линейное количество операций (слияние).
Следовательно, общая сложность — произведение глубины рекурсии и объема работ на каждом уровне: O(log⁡n)×O(n)=O(nlog⁡n)O(logn)×O(n)=O(nlogn).

Сортировка Шелла (Shellsort) — является модификацией сортировки вставками, сортирует между собой элементы, стоящие на местах, кратных определённому шагу.
Анализ алгоритма:
Внешний цикл: while gap > 0: контролирует изменение шага (gap).
Внутренний цикл: for i in range(gap, len(arr)): осуществляет просмотр массива, начиная с позиции, равной текущему шагу (gap), и проходя по остальным элементам.
Подцикл внутри внешнего цикла: while j >= gap and arr[j-gap] > temp: отвечает за перемещение элементов массива.
Обмен элементов: arr[j] = arr[j-gap] передвигает элемент, находящийся на расстоянии шага (gap), на позицию j, тем самым освобождая место для вставки текущего элемента (temp).
Обмен элементов: arr[j] = temp помещает элемент temp на позицию j, которая теперь свободна после сдвига предыдущих элементов
Временная сложность алгоритма: O(n²)
Почему O(n²): Алгоритм использует вложенные циклы, но внутренний цикл (по j) не всегда проходит n раз, как в пузырьке. Количество итераций зависит от gap. В среднем случае количество итераций внутреннего цикла растет медленнее, чем n, приводя к сложности O(n^2).

Быстрая сортировка (Quick Sort) — алгоритм состоит в выборе опорного элемента, разделении массива на две части относительно опорного (одна — все элементы, меньшие опорного элемента, вторая — большие), и в сортировке полученных частей рекурсивным вызовом себя от них.
Анализ алгоритма:
Опорная точка: Мы выбираем середину массива в качестве опорного элемента: pivot = arr[len(arr) // 2]
Формирование трех списков: Используя list comprehension, мы создаём три отдельные части:left: элементы, меньшие опорного; middle: элементы, равные опорному; right: элементы, большие опорного.
Рекурсивная сортировка:Теперь мы рекурсивно вызываем функцию quick_sort для левого и правого списков: return quick_sort(left) + middle + quick_sort(right). Рекурсивные вызовы продолжаются до тех пор, пока не останутся только небольшие части, которые уже можно считать отсортированными.
Временная сложность алгоритма: O(n²)
Почему O(n²): возникает в редких случаях (например, когда массив уже отсортирован и выбирается плохой опорный элемент).

Пирамидальная сортировка — алгоритм строит кучу из исходного списка, затем постепенно
извлекает наибольший элемент из кучи и помещает его в конец списка.
 Анализ алгоритма:
Функция(внешний цикл): void heapify(vector<int>& arr, int n, int root): предназначена для поддержания свойств кучи. Она получает массив (arr), его размер (n) и индекс корневого узла (root), и восстанавливает кучу, следуя принципу: родитель всегда больше детей.
Функция: void heapSort(vector<int>& arr): организует процесс сортировки, состоящий из двух главных этапов: создает max-кучу и выполняет сортировку.
Обмен элементов происходит, если нарушено свойство кучи (родитель меньше ребёнка): swap(arr[root], arr[largest]).
Явного внутреннего цикла нет, так как структура данных поддерживается рекурсивно.
Временная сложность алгоритма: O(n log n)
Почему O(n log n): Это связано с тем, что каждый элемент перемещается в верхнюю часть кучи за O(log n), а операция повторяется n раз.

Алгоритмы поиска 

Последовательный (линейный) поиск — это алгоритм поиска заданного элемента на некотором множестве, при котором каждый элемент проверяется по порядку, пока не будет найден искомый элемент или не завершится просмотр всех элементов.
Анализ алгоритма:
Функция линейного поиска:def linear_search(arr, target):Определена функция linear_search, которая принимает два аргумента: arr — массив, в котором ведется поиск; target — искомое значение.
Перебор элементов массива:for index, value in enumerate(arr):Оператор enumerate позволяет одновременно получать индекс и значение каждого элемента массива.
Проверка условий:if value == target:Если текущий элемент массива совпадает с искомым значением, функция немедленно возвращает индекс этого элемента.
Временная сложность алгоритма: O(n)
Почему O(n): В худшем случае (когда элемент находится в конце массива или вовсе отсутствует) приходится просмотреть все элементы массива.

Бинарный (двоичный, дихотомический) поиск — это поиск заданного элемента на упорядоченном множестве, осуществляемый путём неоднократного деления этого множества на две части таким образом, что искомый элемент попадает в одну из этих частей. Поиск заканчивается при совпадении искомого элемента с элементом, который является границей между частями множества или при отсутствии искомого элемента.
Анализ алгоритма:
Функция бинарного поиска:def binary_search(arr, target):Аргументами функции служат отсортированный массив arr и искомое значение target.
Основной цикл поиска:while low <= high:Поиск продолжается, пока нижняя граница не превышает верхнюю.
Вычисление среднего индекса:mid = (low + high) // 2. Рассчитывается индекс центрального элемента, который сравнивается с целью поиска.
Обновление границ поиска: 
Если искомое значение меньше среднего:high = mid - 1Поиск продолжается в левой половине массива.
Если искомое значение больше среднего:low = mid + 1Поиск продолжается в правой половине массива.
Временная сложность алгоритма: O(log n)
Почему O(log n): так как на каждом шаге область поиска сокращается вдвое, требуемое количество шагов растет логарифмически относительно размера массива.

Интерполирующий поиск- это алгоритм поиска для отсортированных наборов данных,
таких как массивы или списки. Он предсказывает позицию нужного элемента на основе
разницы значений. 
Анализ алгоритма:
Функция поиска:int interpolationSearch(int arr[], int n, int target) {Функция принимает массив arr, его размер n и искомое значение target.
Основной цикл поиска:while ((low <= high) && (target >= arr[low]) && (target <= arr[high]))Цикл продолжается, пока нижняя граница не превзойдет верхнюю и пока искомое значение находится в границах массива.
Особый случай:if (low == high) { if (arr[low] == target) return low; return -1;}Если границы сошлись в одну точку, проверяем единственную возможную позицию.
Интерполяционная формула:int pos = low + (((double)(high - low) / (arr[high] - arr[low])) * (target - arr[low]));Рассчитывается предполагаемая позиция искомого элемента, учитывая распределение значений в массиве.
Временная сложность алгоритма: O(n)
Почему O(n): если распределение элементов неравномерно или совсем плохо организовано (например, возрастающие подряд одинаковые значения).

Поиск по Фибоначчи — это эффективный алгоритм поиска, используемый для нахождения целевого значения в отсортированной коллекции, такой как массив или список. По принципу он аналогичен бинарному поиску, но использует числа Фибоначчи для определения позиций для сравнения.
Анализ алгоритма:
Генерация чисел Фибоначчи:fib_m_minus_2 = 0fib_m_minus_1 = 1fib_M = fib_m_minus_2 + fib_m_minus_1Генерируются числа Фибоначчи, пока самое большое число не станет больше длины массива.
Основной цикл поиска:while fib_M > 1:Поиск продолжается, пока текущее число Фибоначчи больше 1.
Расчёт индекса для проверки:i = min(offset + fib_m_minus_2, len(arr)-1)Вычисляется индекс элемента, который будем проверять на текущем шаге.
Особая проверка последнего элемента:if fib_m_minus_1 and arr[offset+1] == target: return offset + 1Дополнительно проверяем последний возможный элемент.
Временная сложность алгоритма: O(log n)
Почему O(log n): аналогичный бинарному поиску, но в ряде случаев (особенно при большом разбросе данных) может показывать лучшую производительность за счёт большей гибкости выбора точек разделения.
