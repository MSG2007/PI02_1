ВАРИАНТ 13. Жадный алгоритм для задачи о распределении ресурсов.
Задача: реализовать жадный алгоритм для оптимального распределения ресурсов среди проектов.
Требования:
- Каждый проект имеет требуемый ресурс и приносит прибыль
- Общий объем ресурсов ограничен
- Выбрать проекты для максимизации прибыли
Входные данные:
Проекты: {(ресурс=10, прибыль=50), (ресурс=15, прибыль=80), (ресурс=20, прибыль=90), (ресурс=8, прибыль=40)}
Общий ресурс: 40

I)Анализ алгоритма:
1) Ввод исходных данных.
  Пользователь задаёт:
  -общий ресурс (total_resource);
  -количество проектов (num_projects);
  -для каждого проекта (resource и profit).
2) Вычисление эффективности проектов.
Для каждого проекта рассчитывается показатель эффективности, равный отношению прибыли к расходованию ресурса. Чем больше значение этого отношения, тем выгоднее включить проект в решение.
    for project in projects:
        project['efficiency'] = project['profit'] / project['resource']
3) Сортировка по убыванию эффективности.
Проекты упорядочиваются от самого «выгодного» к наименее выгодному: projects.sort(key=lambda x: x['efficiency'], reverse=True).
4) Последовательный отбор проектов.
Начиная с наиболее эффективных проектов, проверяется, хватит ли оставшихся ресурсов для включения очередного проекта. Если да, то проект добавляется в решение, и обновляются общие показатели: занятые ресурсы увеличиваются, а прибыль накапливается. Ключевое условие: проверка if total_used_resource + project['resource'] <= total_resource гарантирует, что мы не превысим лимит.
5) Вывод результатов.
По окончании цикла программа показывает: выбранные проекты (с их параметрами), общую использованную ресурсную базу, итоговую прибыль, остаток неиспользованных ресурсов.

II) Временная сложность: O(n log n), где n-количество проектов.
III) Объяснение временной сложности: Поскольку самой дорогой операцией является сортировка, которая выполняется за O(n log n), именно её вклад определяет итоговую временную сложность всего алгоритма. Поэтому итоговая асимптотическая оценка временной сложности алгоритма такая.

13. Табу-поиск.
Объясните концепцию табу-листа в алгоритме табу-поиска. Какую роль он играет?
Табу-лист в алгоритме табу-поиска — это структура данных (обычно очередь ограниченного размера), где хранятся недавние решения или ходы, которые временно запрещено повторять. Его главная цель — предотвратить зацикливание алгоритма в локальных оптимумах путём исключения недавно проверенных вариантов. Таким образом, алгоритм вынужден искать новые пути решения проблемы, увеличивая шансы на обнаружение глобального оптимального решения. Табу‑лист реализует краткосрочную память алгоритма: он хранит лишь ограниченное число последних ходов (размер списка — настраиваемый параметр) и старые записи постепенно вытесняются новыми. Табу-лист позволяет расширить пространство поиска и избежать преждевременной остановки процесса оптимизации.
