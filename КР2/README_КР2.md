Задание 5. Имитация отжига: оптимизация функции
Условие. Минимизировать f(x)=x 2 на [−10,10] методом имитации отжига.
Алгоритм: имитация отжига (Simulated Annealing).
Язык примера: Java
public static double saSquare(double temp, double cooling) {
double x = Math.random() * 20 - 10;
double energy = x * x;
while (temp > 1e-6) {
double xNew = x + (Math.random() * 2 - 1) * temp;
double energyNew = xNew * xNew;
// ДОПИСАТЬ: принять/отклонить xNew по критерию Метрополиса
temp *= cooling;
}
return x;
}
Что дописать: условие принятия нового решения.

I. Анализ алгоритма:
Шаг 1. Инициализация.
double x = Math.random() * 20 - 10;  
double energy = x * x;            
Выбираем начальное x случайно на отрезке [−10, 10]. Вычисляем начальное значение функции («энергию») energy = f(x).
Шаг 2. Основной цикл (по температуре).
while (temp > 1e-6) {
    // ...
    temp *= cooling;
}
Цикл работает, пока температура temp больше порога 10⁻⁶. На каждой итерации температура умножается на коэффициент cooling (0 < cooling < 1).
Шаг 3. Генерация нового состояния.
double xNew = x + (Math.random() * 2 - 1) * temp;
double energyNew = xNew * xNew;
Генерируем новое xNew в окрестности текущего x. Амплитуда шага: ±temp (зависит от текущей температуры). Вычисляем «энергию» нового состояния: energyNew = f(xNew).
Шаг 4. Критерий Метрополиса (принятие/отклонение).
if (energyNew < energy || 
    Math.random() < Math.exp((energy - energyNew) / temp)) {
    x = xNew;
    energy = energyNew;
}
Если новое состояние лучше (energyNew < energy), принимаем его. Если хуже, принимаем с другой вероятностью. Это позволяет иногда «подниматься в гору», чтобы избежать локальных минимумов.
Шаг 5. Охлаждение.
temp *= cooling;
Уменьшаем температуру: temp ← temp · cooling. С понижением temp: амплитуда шагов сокращается; вероятность принятия ухудшений падает.
Шаг 6. Завершение.
Когда temp ≤ 10⁻⁶, цикл завершается. Возвращается текущее x.

II. Временная сложность
Итоговая оценка: T(n)=O( ln(temp₀)/∣ln(cooling)∣), где:temp₀ — начальная температура; cooling — коэффициент охлаждения (0 < cooling < 1).

III. Получение временной сложности: 
Временная сложность алгоритма имитации отжига — O(ln(temp₀) / |ln(cooling)|). Она определяется числом итераций цикла, в котором температура temp на каждом шаге умножается на коэффициент cooling (0 < cooling < 1): tempₖ = temp₀ · coolingᵏ. Цикл завершается, когда temp падает до порога 10⁻⁶. Решая неравенство temp₀ · coolingᵏ ≤ 10⁻⁶ через логарифмирование, получаем, что число итераций k пропорционально ln(temp₀) / |ln(cooling)|. Поскольку каждая итерация выполняется за O(1), общая сложность совпадает с оценкой числа итераций. Таким образом: при росте начальной температуры temp₀ число итераций увеличивается логарифмически; при приближении cooling к 1 число итераций растёт (охлаждение замедляется).

5. Жадный алгоритм для рюкзака
Почему жадный алгоритм для 0-1 рюкзака не гарантирует оптимальное решение? Приведите
контрпример.
Жадный алгоритм, выбирающий предметы по убыванию удельной стоимости (стоимость/вес), не гарантирует оптимальность для задачи 0-1 рюкзака, потому что он не учитывает, что выбор выгодного предмета может помешать взять несколько менее выгодных предметов, которые в сумме дают большую общую стоимость.
Контрпример:
Вместимость рюкзака: 3
Предметы:
Вес = 2, Стоимость = 3 (удельная стоимость = 1.5)
Вес = 2, Стоимость = 2 (удельная стоимость = 1)
Вес = 1, Стоимость = 2 (удельная стоимость = 2)
Жадный алгоритм (по удельной стоимости):
Предмет 3 (удел. стоимость = 2)
Предмет 1 (удел. стоимость = 1.5)
Суммарный вес: 1 + 2 = 3.
Итоговая стоимость: 2 + 3 = 5.
Оптимальное решение:
Предмет 1 (вес 2, стоимость 3) и Предмет 2 (вес 2, стоимость 2) не влезут вместе.
Предмет 2 (вес 2, стоимость 2) и Предмет 3 (вес 1, стоимость 2):
Суммарный вес: 2 + 1 = 3.
Итоговая стоимость: 2 + 2 = 4.
Вывод: Жадный алгоритм взял предметы 1 и 3, получив стоимость 5. Однако оптимальное решение — взять предметы 2 и 3, получив стоимость 4. В данном случае жадный алгоритм дал лучшее решение, чем оптимальное, что доказывает, что он не всегда находит оптимальное.
